## 〇、现状结论（先说三句）

1. **你已经有一套自洽的 UI 体系，缺的不是重构而是「资产补齐 + 锚点固化」。** `assets/css/rpg-theme.css`（1300+ 行）用 `--rpg-*` 语义变量驱动全部 51 个组件，稀有度四档配色、琥珀经验系、紫罗兰钻石系已经锁定在代码里——**这些是已确认设计，本提案不改，只收编成规范**。
2. **风格事实：这是「科技奇幻（Cyber-Fantasy）」混搭，不是像素风。** 柔和弥散光晕阴影 + 渐变面板 + Q 版图标 + emoji 回退，与博客壳层的 cyber 深色科技主题共享 `tech-shell` 变量。像素风硬边、手绘描边都与你现有体系冲突，禁止引入。
3. **最大缺口在图片资产**：`public/rpg/icons/` 约 90 个键（128px 透明底 PNG + SVG 兜底，2026-10 AI 生成）质量参差且无统一锚点约束；`public/rpg/art/` 仅 6 张大图；`equipment` 物品类型在数据模型里已定义但无独立 UI。**本提案的目标是：让后续每一张新图都长在同一张脸上。**

## 一、风格锚点 v1（逐字复用段）

```
【风格锚点 v1 · blog-rpg】
画风：2D 科技奇幻扁平风，渐变面板 + 柔光质感，无描边硬边，非像素风；
     图标与宠物为 Q 版微缩插画（圆润剪影、大眼睛比例、单主体居中）
视角：图标正面四分之三，物品正俯视 45 度；大图立绘正面全身
光照：左上 45 度柔光主光 + 底部环境反光，金属/宝石类允许一处锐利高光点；
     禁止多光源、禁止体积光特效
线宽：无外描边；用明度差与内阴影区分轮廓，边缘柔和过渡 1-2px
质感：哑光渐变底 + 细腻内发光（inset highlight），金属与稀有材质
     允许镜面渐变条，但高光面积 ≤ 主体面积 15%
比例：物品图标单主体占画布 70-80%，留 10-15% 安全边；
     宠物 Q 版二至三头身，头部占比 ≥ 40%
色彩倾向：中高饱和奇幻色为主，琥珀金与紫罗兰为品牌双主色，
     青色仅作科技点缀；背景一律中性深灰或纯透明
禁忌：① 不写实人体解剖与写实毛发；② 不用像素风/硬描边/赛璐璐分块；
     ③ 不模仿任何现有游戏 IP 的专属形象（宝可梦/原神/炉石等）；
     ④ 同一张图不超过 3 种高饱和色；⑤ 图标内不出现文字与水印
```

**自检**：八字段齐 ✅ 禁忌 5 条 ✅ 双模式要求见下节 ✅

## 二、色彩板（收编自 rpg-theme.css，色号已锁定）

### 2.1 核心六色

| 角色 | 用途 | 色号 | 明度 L | 来源 |
|---|---|---|---|---|
| 琥珀金（品牌主色） | 经验、等级、传说稀有度、主 CTA | `#F59E0B`（亮部 `#FBBF24`） | ~70 | `--rpg-amber` |
| 紫罗兰（品牌辅色） | 钻石货币、宠物系、史诗稀有度 | `#7C5CF0` | ~52 | `--rpg-violet` |
| 青色（科技点缀） | 链接、次级交互、科技感点缀 | 取自 cyber 主题 `oklch(75% 0.15 195)` ≈ `#3EC8D5` | ~75 | daisyUI primary |
| 生命绿 | HP > 60% | `#4ADE80` | ~72 | `--rpg-life` |
| 危险红 | HP 低、惩罚、扣减 | `#EF4444` | ~58 | `--rpg-danger` |
| 中性面板底 | 面板/卡片背景 | 暗模式 `#1E2230` 系 / 亮模式白系 | 12 / 98 | `--rpg-panel-bg` |

**硬规则**：主体与背景明度差 ≥ 2 档（现有暗底面板 + 亮色内容天然满足）；同屏高饱和色 ≤ 3 种；**状态不只靠颜色**——HP 三态已配文案（状态良好/注意危险/即将归零）✅，稀有度徽章已配文字标签 ✅，保持。

### 2.2 稀有度四档（已锁定，逐字照抄）

| 档位 | 主渐变 | 语义 |
|---|---|---|
| Common | 银灰 `#9CA3AF → #6B7280` | 基础物资 |
| Rare | 绿 `#34D399 → #059669` | 进阶 |
| Epic | 紫 `#A78BFA → #7C3AED` | 稀有，带微光 |
| Legendary | 琥珀金 `#FCD34D → #D97706` | 最高档，金光 |
| （特判）银色金属 | 银白渐变，仅限指定物品 code | RpgItemIcon 已有逻辑 |

**规则**：任何新图标、新 UI 的稀有度表现**只允许**用这四档，不得新增第五档颜色；金光/紫光动效强度 Legendary > Epic，Rare 及以下无光效。

### 2.3 明度阶梯

| 层级 | L 区间 | 落点 |
|---|---|---|
| 高光/强调 | 80–95 | 传说金亮部、钻石高光点 |
| 主体亮面 | 60–80 | 图标受光面、经验条渐变 |
| 主体中间调 | 40–60 | 图标固有色、紫罗兰 |
| 主体暗部 | 20–40 | 渐变收尾、内阴影 |
| 背景 | ≤ 15（暗）或 ≥ 95（亮） | 面板底 |

**验证**：整张 UI 截图转灰度后，卡片、图标主体、稀有度徽章三层仍可分辨即为合格。

## 三、UI 组件规范（收编现有代码 + 补缺）

### 3.1 几何与阴影（已锁定）

| 元素 | 圆角 | 阴影 |
|---|---|---|
| 面板 Panel | 14–16px | `0 16px 48px rgb(0 0 0 / 0.28)` 弥散光晕 + inset 高光 |
| 格卡 LootCard | 12px | 同上，减淡一档 |
| 图标容器 | 8 / 10 / 12 / 20px（对应 sm28/md34/lg52/xl88） | 稀有度 tint 底色 |
| 徽章/胶囊 | 999px | 无 |
| 进度条（EXP/HP） | 全圆角，高 6–10px | 渐变填充 + 端头发光 |

**新组件一律先从 `rpg-theme.css` 取变量，禁止组件内硬编码色值**（现有 `var(--rpg-violet, #7c5cf0)` 的写法只允许作为降级 fallback）。

### 3.2 字体

- 正文/UI：HarmonyOS Sans SC（已子集化预载）
- 等级数字/伤害数值/奖励数值：等宽 `ui-monospace`，可选 `Instrument Serif` 做大号仪式感数字（如升级动画）
- 禁止在游戏 UI 内引入第三种字体

### 3.3 各系统 UI 要点与缺口

| 系统 | 现状 | 缺口/待办 |
|---|---|---|
| 状态/签到 | ProfileCard + StatusPanel 双轨，琥珀 EXP + 三态 HP | ✅ 齐全；建议择一保留避免风格漂移 |
| 背包 | loot-grid + LootCard + 稀有度徽章 | ✅ 体系完整，是全站风格基准 |
| 宠物 | 蛋 6 种 + 出战大图位 88px | **缺宠物立绘大图**（现只有 88px 小图标撑 hero 位，应补 512px 立绘） |
| 抽奖 | 三阶段动画 + 保底 | ✅ 动效完整；传说揭晓帧需要 1 张传说品质主视觉图 |
| 商店/充值 | 弹窗承担 | 缺钻石礼包视觉（可复用 diamond 图标放大 + 琥珀渐变底） |
| 任务/成就 | emoji 图标 map | **emoji 与图片图标混用是当前最大风格破绽**，P1 批次替换为统一 128px 图标 |
| 公会/排行 | 纯 UI | 可维持现状；赛季横幅 SeasonBanner（1028 行）建议换用 1 张赛季主题横幅图 |
| 装备 equipment | 类型已定义，无 UI | 立项待定（见第六节批次） |

### 3.4 动效语言（已锁定基调）

- 缓动：弹性出场（scale overshoot）+ 呼吸循环（NavHud badge 已有）
- 光效层级：Legendary 金光粒子 > Epic 紫光 > 其他无光效
- 数字跳动：等宽字体 + 逐位滚动
- 音效已由 Web Audio 合成，无需美术配乐交付

## 四、图标资产规范（对齐 README 已有约定）

| 项 | 规格 |
|---|---|
| 尺寸 | 128×128px，透明底 PNG（主交付）+ 同名 SVG 兜底 |
| 主体占比 | 70–80%，四周 10–15% 安全边 |
| 风格 | 锚点 v1 逐字进提示词；同族物品共用同一组辅色 |
| 命名 | 沿用 icon 键体系（90 个键已固化，如 `egg-fox`、`frame-gold`、`medal-gold`） |
| 登记 | 新增键必须登记 `utils/rpg-item-asset.ts` 的 `RPG_ICON_ASSET_KEYS` / `RPG_ICON_RASTER_KEYS`，否则走 emoji 回退 |
| 标注 | AI 生成一律记录版本号与提示词版本，存 `public/rpg/icons/README.md` |
| 禁止 | 图标内出现文字、水印、复杂背景、超过 3 种高饱和色 |

**回退链不变**：管理端 `iconUrl` → 本地 png/webp/svg → emoji。emoji 只是兜底，不是风格的一部分——**目标状态是 90 键全部有图，emoji 零出镜**。

## 五、一致性检查（三道，每批资产必跑）

1. **同族比对**：所有宠物（cat/fox/dragon/kirin/owl/phoenix/slime）拼一张接触表——统一头身比、眼距、高光位置。
2. **同对象状态比对**：同一物品的普通/稀有变体并排——只换稀有度 tint 与光效，不换造型结构。
3. **跨类别比对**：图标 + 面板 UI + 横幅大图同屏——横幅图饱和度必须压低一档，避免抢过图标主体。

工具：`art_asset_tools.py sheet <dir>`；新图标批次先出 1–2 张基准图确认，再放量。
